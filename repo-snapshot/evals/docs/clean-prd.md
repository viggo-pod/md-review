# 《轻步》健身习惯打卡 App 产品需求文档（PRD）

> 版本：v1.2 | 状态：已评审 | 产品：林晓 | 最后更新：2026-07-30

## 1. 背景（Background）

据《2025 国民健康报告》（国家体育总局公开年度报告），国内 18-45 岁人群中约 61% 有规律运动意愿，但仅 23% 能坚持 3 个月以上，主要障碍是缺少可量化的进度反馈与同伴督促。市面健身类 App 分为两类：专业训练型（门槛高、上手慢）与简单计步型（无目标、无激励）。《轻步》定位于两者之间——以"每日打卡 + 渐进目标 + 好友轻社交"为核心，用最小功能集帮助用户建立运动习惯。市场窗口：2026 年健康打卡类应用增速约 18%（艾瑞咨询行业报告），付费订阅意愿集中在 10-30 元/月区间（问卷调研，样本 1200 人）。

## 2. 目标用户（Target Users）

| 画像 | 年龄 | 场景 | 核心诉求 |
|---|---|---|---|
| 久坐上班族 | 24-35 | 通勤/午休快走 | 低门槛打卡、防打扰提醒 |
| 产后恢复女性 | 28-40 | 居家轻运动 | 温和计划、进度可视化 |
| 大学生 | 18-24 | 校园跑步/球类 | 好友比拼、成就系统 |

## 3. 用户故事（User Stories）

- 作为久坐上班族，我希望每天中午只花 10 分钟完成打卡，以便不占用工作精力也能坚持记录。
- 作为产后恢复女性，我希望运动计划可以按身体状态手动降低强度，以便不在身体不适时被迫达标。
- 作为大学生，我希望看到好友的连续打卡天数，以便通过良性竞争维持习惯。
- 作为有强迫症的用户，我希望打卡失败时可以补卡（每月 3 次），以便连续记录不被意外中断。

## 4. 需求清单（Requirements List）

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| FR-1 | 每日打卡 | P0 | 记录运动类型、时长、强度，生成当日打卡记录 |
| FR-2 | 目标设定 | P0 | 用户设定每周运动天数与每日时长目标（1-180 分钟） |
| FR-3 | 进度看板 | P1 | 周/月视图展示完成率、连续天数、总时长 |
| FR-4 | 提醒推送 | P1 | 每日自定义提醒时段，可关闭；关闭后不再打扰 |
| FR-5 | 好友互动 | P2 | 好友排名、点赞、成就分享（需好友授权） |
| FR-6 | 补卡机制 | P1 | 每月 3 次补卡额度，补卡需填写补卡原因 |
| FR-7 | 运动模板 | P2 | 内置 12 套运动模板（快走/跑步/瑜伽/拉伸等） |
| FR-8 | 数据导出 | P2 | 以 CSV 导出本人打卡数据（隐私合规） |

依赖关系：FR-1 依赖 FR-2（目标存在才可判定打卡达标）；FR-3 依赖 FR-1/FR-2；FR-5 依赖 FR-1；FR-6 依赖 FR-1。

## 5. 功能与非功能需求

### 5.1 功能描述

- **打卡流程**：选择运动模板（或自定义）→ 填写时长（1-180 分钟整数，0 被拒绝）与强度（低/中/高）→ 提交 → 生成打卡记录并更新连续天数。
- **达标判定**：当日时长 ≥ 目标时长且强度不为"低"记为达标；否则记为"已打卡未达标"。
- **连续天数规则**：达标日连续天数 +1；已打卡未达标日或未打卡日连续天数归零。
- **周完成率**：看板周完成率 = 本周达标打卡天数 ÷ 每周运动天数目标 × 100%，用于 FR-3 周视图展示（周目标由 FR-2 设定）。
- **补卡**：每月 1 日重置额度为 3；补卡可补最近 7 天内的任意未打卡日；补卡后该日按达标/未达标重新判定。
- **提醒**：每个提醒时段触发一次本地通知；应用内关闭开关立即生效，关闭后当日不再触发。

### 5.2 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 首页冷启动 ≤ 2 秒；打卡提交 P95 ≤ 500ms；进度看板加载 P95 ≤ 1.5 秒 |
| 可用性 | 月度可用性 ≥ 99.9%（统计异常不可用时间） |
| 安全 | 打卡数据 TLS 加密传输；账号注销后 30 天内彻底删除数据 |
| 兼容 | iOS 15+ 与 Android 10+；最低支持分辨率 360×640 |
| 隐私 | 好友排名默认关闭，需用户显式开启；仅展示连续天数与总时长，不展示精确位置 |

## 6. 范围定义（Scope）

**In-Scope**：打卡、目标、看板、提醒、好友排名（opt-in）、补卡、模板、导出。
**Out-of-Scope**：付费订阅、教练在线指导、穿戴设备深度对接（仅预留心率接口位）、社区内容流。
**本期不做**：多设备实时同步（首期仅单设备 + 云端备份恢复）。

## 7. 验收标准（Acceptance Criteria）

- FR-1：提交任意合法打卡（类型非空、时长 1-180、强度三选一）后，打卡记录在 3 秒内出现在"今日"视图；达标日连续天数 +1、已打卡未达标/未打卡日归零。
- FR-2：目标时长保存后立即生效；下一日 0 点起以新目标判定达标；非法输入（0、负数、>180）被拒绝并提示范围；每周运动天数目标（1-7 天）同样即时生效并参与周完成率计算。
- FR-3：周完成率 = 本周达标打卡天数 ÷ 每周运动天数目标 × 100%，在看板周视图中显示且与打卡记录一致（可抽查任一周验证）。
- FR-4：任一提醒时段开启后，当日到点触发通知；关闭开关后 10 秒内不再有任何提醒（含队列内待发）。
- FR-5：好友排名开启后，本人与好友的连续天数、总时长在 10 秒内刷新；关闭后 1 分钟内对外不可见。
- FR-6：每月最多补卡 3 次；第 4 次补卡请求被拒绝并提示额度已用完；补卡记录带原因且可在导出中追溯。
- FR-7：12 套运动模板全部可选用；任一模板在无自定义时也能完成打卡（默认时长 30 分钟、中强度）。
- FR-8：CSV 导出内容包含打卡日期、类型、时长、强度、是否达标、补卡标记，且与看板数据一致。
- 回归基准：现有核心流程（打卡/达标/看板）全量测试通过，无 P0/P1 缺陷遗留。

## 8. 边界与异常（Edge Cases）

- 时区变更：用户跨时区飞行后，打卡日以设备当前时区 0 点切分；补卡窗口按打卡日（而非自然日）计算。
- 极端输入：时长输入 1 与 180 边界值均合法；0、负数、180 分钟以上拒绝并提示范围；强度字段缺失时提交按钮置灰。
- 服务器超时：打卡提交超时 → 本地暂存并重试 3 次，重试仍失败则提示"稍后自动同步"。
- 重复提交：同一分钟内的重复打卡请求返回原记录（幂等键=日期+用户ID），不重复计数。
- 账号注销：注销后立即停用账号；30 天内可申诉恢复，30 天后数据物理删除。

## 10. 流程图（Flow）

打卡主流程：打开应用 → 选择模板/自定义 → 填写时长与强度 → 提交 → 服务端校验（时长范围/幂等）→ 写入记录 → 更新连续天数 → 看板刷新。异常分支：网络失败 → 本地暂存重试；校验失败 → 表单错误提示。

## 11. 数据需求（Data Requirements）

核心表：`user`（用户档案）、`daily_checkin`（每日打卡：日期、类型、时长、强度、是否达标、补卡标记）、`user_goal`（目标：每周天数、每日时长）、`friend_visibility`（好友可见性开关）。关键索引：`daily_checkin(user_id, date)` 唯一索引保证幂等；`user_goal(user_id)` 单行。数据量预估：单用户年打卡记录 ≤ 400 行，首期 10 万 DAU 规模下日均写入 ≤ 40 万行，单表分区按月存储即可满足。

## 13. 成功指标（Tracking / Metrics）

- 核心指标：7 日留存率（目标 ≥ 45%）、月连续打卡 21 天以上用户占比（目标 ≥ 18%）。
- 辅助指标：提醒开启率 ≥ 60%；补卡使用率 ≤ 40%（过高说明目标设定不合理）；好友 opt-in 率 ≥ 35%。
- 北极星指标：人均每周有效打卡天数 ≥ 4 天。

## 14. 5W1H 检查

- **Who**：久坐上班族、产后恢复女性、大学生。
- **What**：每日运动打卡 + 渐进目标 + 好友轻社交。
- **When**：通勤/午休/晚间，每日任意时段一次，用时 1-5 分钟。
- **Where**：手机 App（iOS/Android），支持桌面端仅浏览。
- **Why**：61% 有运动意愿但仅 23% 坚持——缺量化反馈与同伴督促。
- **How**：低门槛打卡 + 达标判定 + 看板激励 + 好友排名，全流程 3 步以内。
