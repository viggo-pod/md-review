# Research Scenario Checklist — Domain Borrow / Research Analysis

当场景参数为 `research` 时启用。检查领域研究或借鉴分析是否可验证、可复用，并能被后续决策或产品设计安全使用。

## Core Questions

1. 研究结论是否能定位到实际来源和证据位置？
2. 借鉴、改写、拒绝是否与本产品边界区分？
3. 许可证、事实不确定性和证据缺口是否明确？

## Key Focus

研究范围 + 来源证据 + 借鉴映射 + 许可证/风险 + 缺口

## Required Content — count-based scoring

### Research Scope and Sources

- [ ] **Research Question**：是否说明研究问题、目标产品和排除范围？
- [ ] **Source Register**：每个来源是否有名称、版本/日期、路径或 URL？
- [ ] **Evidence Location**：每个关键结论是否有文件、行号、代码符号或网页位置？
- [ ] **Author and Date**：是否记录分析作者或责任方和分析日期？

### Borrowing Analysis

- [ ] **Target Mapping**：是否逐项说明外部对象与本地目标、约束或决策的映射？
- [ ] **Adopt / Adapt / Reject**：是否区分直接采用、改写借鉴和不采纳？
- [ ] **Adaptation Boundary**：改写后的产品边界、差异和非目标是否说明？
- [ ] **License Boundary**：许可证、源码复用条件和合规限制是否记录？
- [ ] **Alternative / Anti-pattern**：不采纳项、反模式或替代方案是否有理由？

### Evidence Gaps and Handoff

- [ ] **Confidence**：事实、推断和待验证结论是否区分？
- [ ] **Gap Register**：证据缺口是否记录影响、状态和补证动作？
- [ ] **Decision Mapping**：结论是否映射到明确的本地需求、决策、能力或其他目标条目？
- [ ] **Handoff Boundary**：是否明确预期消费者和交接边界，且没有把借鉴能力声明成已实现？

### 5W1H Check

- [ ] **Who**：谁提供来源、谁消费研究结论？
- [ ] **What**：研究了什么能力或领域？
- [ ] **Why**：为什么研究，解决哪个决策问题？
- [ ] **When**：来源和分析何时有效？
- [ ] **Where**：来源和证据位于何处？
- [ ] **How**：如何复核、改写或拒绝该借鉴点？

## Completeness Issue Markers

- 只有结论，没有可定位证据
- 把外部项目能力直接当成本产品需求
- 缺少许可证或源码复用边界
- 研究文件没有作者或责任方，或没有说明预期消费者和使用边界
